# Исследование эффективности KV Cache в малых языковых моделях

Экспериментальное исследование компромисса между потреблением GPU-памяти и скоростью инференса при использовании различных стратегий KV Cache.

## Исследовательский вопрос

Как выбор стратегии KV Cache влияет на потребление GPU-памяти и производительность инференса языковой модели при увеличении длины контекста?

Дополнительный вопрос: существует ли длина контекста, начиная с которой стратегии, экономящие GPU-память, становятся практически выгоднее стандартного KV Cache?

## Мотивация

При авторегрессионной генерации Transformer-модели сохраняют key/value состояния предыдущих токенов в KV Cache. Это ускоряет генерацию, однако объём KV Cache растёт вместе с длиной контекста.

Для длинных последовательностей KV Cache может занимать значительную часть GPU-памяти. Существуют различные способы уменьшить это потребление: перенос части кэша в CPU, квантизация, статическое выделение памяти и другие методы.

Цель работы — экспериментально исследовать компромисс между памятью и производительностью для различных стратегий KV Cache.

## Первый эксперимент

### Модель

Qwen3-0.6B

### Оборудование

- NVIDIA Tesla V100-SXM2
- 32 GB GPU-памяти
- кластер НИУ ВШЭ cHARISMa

### Точность

FP16

### Длины контекста

- 512
- 2048
- 4096
- 8192
- 16384 токенов

### Стратегии KV Cache

- DynamicCache
- StaticCache
- Offloaded Cache

### Повторы

Каждая конфигурация запускается несколько раз после предварительного прогрева.

## Измеряемые величины

Для каждой конфигурации сохраняются:

- длина входного контекста;
- стратегия KV Cache;
- время инференса;
- скорость генерации;
- максимальное использование GPU-памяти;
- зарезервированная GPU-память;
- использование оперативной памяти;
- модель GPU;
- версии PyTorch и Transformers;
- информация об ошибках.

## Начальные гипотезы

1. DynamicCache должен давать хороший baseline по скорости, пока KV Cache полностью помещается в GPU-память.

2. Offloaded Cache должен уменьшать использование GPU-памяти ценой дополнительной задержки из-за передачи данных между CPU и GPU.

3. С ростом длины контекста преимущество memory-efficient стратегий должно становиться заметнее.

4. Для некоторых стратегий может существовать crossover point — длина контекста, после которой выигрыш по памяти начинает оправдывать потерю производительности.

5. Квантизация KV Cache потенциально должна быть особенно полезна на длинных контекстах, тогда как на коротких последовательностях дополнительный overhead квантования может сделать её невыгодной.

## План исследования

1. Получить baseline для DynamicCache, StaticCache и Offloaded Cache на Qwen3-0.6B.
2. Разделить измерения prefill и decode.
3. Повторить эксперимент для Qwen3-1.7B и Qwen3-4B.
4. Добавить квантованный KV Cache.
5. Исследовать влияние квантизации KV Cache на качество работы с длинным контекстом.
6. Сравнить экспериментальное потребление памяти с теоретической оценкой размера KV Cache.
7. Найти crossover points между различными стратегиями.

## Текущий статус

Завершён baseline-эксперимент DynamicCache и StaticCache на Qwen3-0.6B
и NVIDIA V100 32 GB с раздельным измерением prefill и decode.

Основные наблюдения:

- фактический размер Dynamic KV Cache совпадает с теоретической оценкой;
- DynamicCache сохраняет примерно постоянный decode throughput до 8192 токенов;
- между 8192 и 16384 наблюдается заметное падение decode throughput;
- StaticCache без compilation примерно на 14% медленнее DynamicCache до 8192 токенов;
- StaticCache с compilation будет исследован отдельно;
- для Offloaded Cache обнаружена отдельная проблема корректности,
  описанная в `notes/offloaded_correctness.md`.

Следующий этап — исследование более длинных контекстов и области
возникновения падения производительности, после чего будет добавлен
квантованный KV Cache.
