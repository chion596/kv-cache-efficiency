# Постановка эксперимента

## Цель

Исследовать влияние стратегии KV Cache на потребление GPU-памяти и производительность инференса при увеличении длины входного контекста.

## Независимые переменные

### Стратегия KV Cache

- DynamicCache
- StaticCache
- Offloaded Cache

В дальнейшем:

- Quantized Cache INT4
- Quantized Cache INT2

### Длина контекста

На первом этапе:

- 512 токенов
- 2048 токенов
- 4096 токенов
- 8192 токенов
- 16384 токенов

### Размер модели

На первом этапе:

- Qwen3-0.6B

В дальнейшем:

- Qwen3-1.7B
- Qwen3-4B

## Зависимые переменные

Измеряются:

- время выполнения;
- число генерируемых токенов в секунду;
- peak allocated GPU memory;
- peak reserved GPU memory;
- использование CPU RAM.

В основной версии benchmark отдельно измеряются:

- время prefill;
- TTFT (Time To First Token);
- decode throughput;
- TPOT (Time Per Output Token);
- теоретический размер KV Cache;
- фактически выделенная память KV Cache на GPU и CPU.

## Контролируемые параметры

При сравнении стратегий фиксируются:

- одна и та же модель;
- один и тот же GPU;
- один тип GPU;
- FP16;
- одинаковая длина output;
- одинаковый способ построения входного текста;
- одинаковые версии библиотек;
- одинаковое число повторов;
- прогрев перед измерениями.

## Первый запуск

Оборудование:

NVIDIA Tesla V100-SXM2 32 GB.

Модель:

Qwen3-0.6B.

Генерация:

64 новых токена.

Число повторов:

3 после warm-up.

## Важные ограничения первого эксперимента

Текущий показатель времени смешивает prefill и decode.

Поэтому первый запуск следует рассматривать как baseline/pilot experiment, а не как окончательное измерение скорости декодирования.

После проверки корректности инфраструктуры необходимо разделить prefill и decode.
