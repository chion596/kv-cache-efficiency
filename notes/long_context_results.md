# Long-context benchmark Qwen3-0.6B

## Конфигурация

- модель: Qwen3-0.6B;
- GPU: NVIDIA Tesla V100-SXM2 32 GB;
- dtype: FP16;
- PyTorch: 2.14.0+cu126;
- Transformers: 5.17.0;
- max_position_embeddings: 40960;
- стратегии: DynamicCache и StaticCache;
- compilation отключена;
- output: 64 токена;
- 5 измерений после warm-up.

Длины контекста:

8192, 10240, 12288, 14336, 16384,
20480, 24576, 32768, 40895.

Все 90 измерений завершились без ошибок.

## Decode throughput

DynamicCache:

- 8192: 32.06 tok/s
- 10240: 31.84 tok/s
- 12288: 28.34 tok/s
- 14336: 25.13 tok/s
- 16384: 22.55 tok/s
- 20480: 18.74 tok/s
- 24576: 16.05 tok/s
- 32768: 12.46 tok/s
- 40895: 10.19 tok/s

StaticCache:

- 8192: 28.03 tok/s
- 10240: 27.41 tok/s
- 12288: 23.24 tok/s
- 14336: 20.31 tok/s
- 16384: 18.08 tok/s
- 20480: 14.95 tok/s
- 24576: 12.71 tok/s
- 32768: 9.80 tok/s
- 40895: 8.02 tok/s

## Начало деградации decode

До context=10240 throughput DynamicCache практически не меняется.

Между 10240 и 12288 наблюдается первое выраженное снижение:
DynamicCache теряет около 11% decode throughput.

После этого производительность продолжает снижаться с увеличением
длины контекста.

Поэтому результат предыдущего baseline следует уточнить:
наблюдаемая деградация начинается уже после примерно 10K токенов,
а не непосредственно на 16K.

Точный дискретный "порог" по этим данным утверждать нельзя:
эксперимент показывает область начала выраженной деградации
между протестированными точками 10240 и 12288.

## DynamicCache и StaticCache

Без compilation StaticCache медленнее DynamicCache на всех
исследованных длинах контекста.

Относительное снижение decode throughput составляет:

- 8192: 12.6%
- 10240: 13.9%
- 12288: 18.0%
- 14336: 19.2%
- 16384: 19.8%
- 20480: 20.2%
- 24576: 20.8%
- 32768: 21.4%
- 40895: 21.3%

Таким образом, после начала long-context деградации относительный
штраф StaticCache без compilation увеличивается примерно до 20-21%.

Этот результат нельзя переносить на StaticCache с torch.compile:
compiled StaticCache необходимо исследовать отдельно.

## Prefill

Время prefill растёт существенно быстрее, чем длина контекста.

Для DynamicCache:

- 8192: 0.413 s
- 16384: 1.276 s
- 24576: 2.662 s
- 32768: 4.578 s
- 40895: 7.063 s

Это соответствует ожидаемому росту стоимости attention при увеличении
длины последовательности, однако по текущим измерениям не следует
приписывать наблюдаемой кривой точную асимптотику.

## KV Cache memory

Для DynamicCache фактически выделенный GPU KV Cache совпадает
с теоретической FP16-оценкой на всех протестированных точках:

- 8192: 0.8750 GiB
- 16384: 1.7500 GiB
- 24576: 2.6250 GiB
- 32768: 3.5000 GiB
- 40895: 4.3681 GiB

Это подтверждает линейное масштабирование памяти KV Cache
с длиной последовательности.

Для StaticCache физический cache немного больше, поскольку память
предварительно выделяется до max_cache_len.

На context=40895 используется max_cache_len=40960, поэтому
StaticCache занимает 4.3750 GiB.

## Peak GPU memory

Даже почти на максимальном нативном контексте Qwen3-0.6B
peak allocated GPU memory составляет приблизительно:

- DynamicCache: 6.529 GiB
- StaticCache: 6.531 GiB

То есть модель всё ещё значительно ниже лимита 32 GB V100.

Поэтому дальнейшее увеличение контекста этой модели за пределы
нативного max_position_embeddings не является следующим основным
экспериментом: для исследования memory pressure полезнее перейти
к memory-efficient cache strategies и/или более крупным моделям.

## Корректность

Для каждой стратегии и длины контекста все 5 повторов дают один
и тот же output hash.

DynamicCache и StaticCache остаются воспроизводимыми во всём
исследованном диапазоне.
